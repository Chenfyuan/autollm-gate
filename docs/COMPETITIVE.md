## 三、我们的差异化（真实存在的两点）

1. **可解释的自动路由**：`model: "auto"` 按请求内容分类（对话 / 编程 / 推理 / 长上下文），按策略打分选模型，每次响应都带 `X-Router-Model / Strategy / Task / Reason` 头，选了谁、为什么选都能看到。主流网关大多只做「指定模型 + 失败兜底」。
2. **不会透支的计费**：按候选模型中最贵的价格预授权冻结余额（条件 UPDATE 原子操作），按实际 token 结算并退回差额。100 路并发、余额只够 10 次的测试里恰好成功 10 次，余额不为负。再加上中文原生的租户控制台，面向国内团队开箱可用。

除此之外的能力（多上游兼容、限流、日志）属于行业标配，我们是在补齐，不算优势。

## 四、差距与优先级

### P0 —— 生产必需（本轮目标）

| # | 项 | 状态 | 验收标准 |
|---|---|---|---|
| P0-1 | Key 级策略：模型白名单、过期、IP 白名单、消费上限 | ✅ v0.3 | 显式请求非白名单模型返回 403；auto 只会选白名单内模型；过期 Key 返回 401；非白名单 IP 返回 403（经 nginx 时按 `TRUST_PROXY` 取真实 IP）；消费达到上限返回 402；修改策略即时生效无需换 Key。均有自动化测试。 |
| P0-2 | 请求日志检索与导出 | ✅ v0.3 | 管理员按租户 / 模型 / 上游 / 状态 / 日期筛选，租户只能查自己的；分页；CSV 导出带 BOM、防公式注入。 |
| P0-3 | 审计日志 | ✅ v0.3 | 后台所有成功写操作自动记录操作人、时间、IP、对象；Key 的创建 / 修改 / 吊销记录策略明细；租户控制台的 Key 操作同样记录。 |
| P0-4 | 跨副本共享熔断 | ✅ v0.3 | 任一副本熔断某上游后写入 Redis，其他副本在冷却期内同样跳过；Redis 不可用时退化为进程内熔断，不影响请求。 |
| P0-5 | Webhook 防 DNS rebinding | ✅ v0.3 | 校验通过的 IP 即实际连接的 IP（保留 Host 头与 TLS SNI），测试证明发送时不会再次解析域名。 |
| P0-6 | Embeddings 接口 | ✅ v0.3 | `/v1/embeddings` 走同一套鉴权、白名单、预授权与计费。 |
| P0-7 | 核心逻辑插件化 | ✅ v0.3 | 公开仓库只保留接口与默认实现；私有核心包安装后通过 entry point 自动加载；加载失败回退默认实现；Docker 构建可选安装，凭据只经 BuildKit secret。 |
| P0-8 | 真实上游适配回归 | 规划中 | 用录制的真实响应样本（不含密钥）做兼容测试；目前只在模拟上游上测过，没有用真实 Key 实测。 |
| P0-9 | 支付对账框架 | 规划中 | 回调验签、幂等入账（已有）、与渠道账单对账任务；在线支付渠道仍为规划中。 |
| P0-10 | 重试 / 超时策略可配置 | ◐ | 已有全局上游超时、连接超时与兜底次数；按路由配置规划中。 |

### P1 —— 追平主流

- 多渠道：同一上游多 Key 加权、优先级、渠道健康检查与自动禁用
- TPM 限流、租户级预算告警
- 精确缓存（Redis，按请求哈希，默认关闭）
- 护栏：PII 脱敏、提示词注入检测（基于现有 hooks）
- 请求正文记录与会话追踪（默认关闭，脱敏后存储）
- 团队成员与角色权限（租户内多成员）
- 更多上游：Azure OpenAI、Bedrock 兼容、Ollama 原生
- 路由规则可视化配置；智能路由评分增强（放在私有核心）

### P2 —— 以后再做

- 图像 / 音频 / 批处理接口、语义缓存、兑换码、SSO / SCIM、提示词版本管理、MCP 网关、多地域部署

## 五、开源与私有的边界

- 公开仓库（本仓库，保留所有权利，仅供查看）：协议兼容层、网关框架、多租户计费框架、管理后台与控制台、**默认**路由评分和默认计价规则（v0.2 起就已公开，历史提交里也有，不改写历史）。
- 私有仓库 `autollm-gate-core`：v0.3 起新增的路由评分增强（按上游健康度加权）和计价规则增强（阶梯折扣等）。以插件形式加载，公开仓库不包含其权重、阈值或公式。
