AutoLLM Gate 是放在你的应用和模型厂商之间的商用网关：自动选模型，上游出错自动切换，每次请求按 tokens 精确计费，自带开发者控制台和运营后台。

功能

把路由、容灾和计费做成一套

不用再分别维护多家 SDK、重试逻辑和账单脚本。

三种协议，一个地址

/v1/chat/completions、/v1/messages、/v1/responses，流式与非流式都支持。现有 SDK 改 Base URL 即可。

model: "auto"

按任务类型和成本选择模型；同一会话固定在同一模型上，多实例之间保持一致。

失败自动切换

上游 429、5xx、超时时切到下一个候选模型；参数错误直接返回，不误切。

按上游熔断

连续失败的上游暂停调用，冷却后放一个探测请求，成功即恢复。

按量精确计费

请求前原子冻结额度，完成后按实际 tokens 结算，并发下不透支。平台与租户两级加价。

控制台与后台

用户自助注册、建密钥、看用量和账单；运营侧看收入、成本、租户与上游健康状况。

监控告警

错误率突增、余额不足、额度将满，推送到飞书、企业微信、钉钉、Slack 或通用 Webhook。

限流

注册、登录按 IP 限流，API 调用按密钥限制每分钟请求数。

密钥加密存储

上游密钥加密落库，界面只显示末 4 位；用户密钥只在创建时显示一次。

工作原理

一次请求经过什么

  1. 01

    鉴权与限流

    校验 API 密钥，检查每分钟请求数。

  2. 02

    冻结额度

    按候选模型中最贵的价格冻结余额，余额不足直接拒绝。

  3. 03

    路由与切换

    选模型并调用上游；出错或被熔断时换下一个候选。

  4. 04

    结算

    按实际 tokens 计费，多退少补，写入账单明细。

接入只改两行
from openai import OpenAI
client = OpenAI(
    base_url="https://<你的网关域名>/v1",
    api_key="<控制台创建的密钥>",
)
client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "你好"}],
)

三种部署形态

  • single

    1 个网关 + Postgres + Redis，适合试用。

  • ha

    2 个网关 + nginx 负载均衡，共享数据库与 Redis。

  • ha,monitoring

    在 ha 基础上加 Prometheus 与预置告警规则。

一条 docker compose up -d 启动，数据库迁移自动执行。
