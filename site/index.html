AutoLLM Gate 是可以部署在你自己服务器上的大模型网关。一个 API 地址接入 OpenAI、Anthropic、Gemini、DeepSeek 与自建模型：自动选模型、上游故障自动切换、按 tokens 预授权计费，并自带租户控制台和运营后台。

为什么需要网关

直连多家模型厂商，问题会越积越多

每家 SDK、鉴权和流式格式都不一样，换一家就要改一遍代码。

统一成 OpenAI、Anthropic、Responses 三种标准协议，业务代码只改 Base URL。

某家上游限流或宕机，线上请求直接报错。

429、5xx、超时自动切到下一个候选；连续失败的上游熔断，多实例同步。

按 tokens 计费、预充值、并发扣费，自己写容易透支或漏账。

请求前原子冻结额度，完成后按实际用量结算，多退少补，并发下不透支。

密钥散落在各个项目里，谁用了什么、花了多少说不清。

每个密钥独立的模型白名单、IP 白名单、有效期与消费上限，请求日志和审计日志可查。

功能

把路由、容灾和计费做成一套

不用再分别维护多家 SDK、重试逻辑和账单脚本。

三种协议，一个地址

/v1/chat/completions、/v1/messages、/v1/responses，流式与非流式都支持；另有 /v1/embeddings 和 /v1/models。现有 SDK 改 Base URL 即可。

model: "auto"

按任务类型和成本选择模型；同一会话固定在同一模型上，多实例之间保持一致。

失败自动切换

上游 429、5xx、超时时切到下一个候选模型；参数错误直接返回，不误切。

按上游熔断

连续失败的上游暂停调用，冷却后放一个探测请求，成功即恢复。v0.3 起一个实例熔断，其他实例同步跳过。

按量精确计费

请求前原子冻结额度，完成后按实际 tokens 结算，并发下不透支。平台与租户两级加价。

控制台与后台

用户自助注册、建密钥、看用量和账单；运营侧看收入、成本、租户与上游健康状况。

监控告警

错误率突增、余额不足、额度将满，推送到飞书、企业微信、钉钉、Slack 或通用 Webhook。

v0.3

密钥访问策略

每个密钥单独设置可用模型（支持 deepseek* 这样的前缀）、IP / CIDR 白名单、有效期、消费上限和每分钟请求数。改完立即生效，不用换密钥。

v0.3

请求日志

每次调用的模型、上游、tokens、费用、耗时和状态都能查。按模型、状态、日期筛选，一键导出 CSV。租户只能看到自己的。

v0.3

审计日志

后台和控制台的每次写操作都会留下记录：谁、什么时候、从哪个 IP、改了什么。

限流

注册、登录按 IP 限流，API 调用按密钥限制每分钟请求数，多实例共用一个计数。

密钥加密存储

上游密钥加密落库，界面只显示末 4 位；用户密钥只在创建时显示一次。

适用场景

谁会用到它

对外提供模型 API 的团队

给客户发密钥、预充值、按用量扣费，自带开发者控制台和运营后台，不用自己写计费系统。

公司内部统一出口

各业务线共用一个网关。每个项目一个密钥，限定可用模型和预算，账单按项目拆分，操作有审计。

需要容灾的线上应用

某家上游限流或宕机时自动换到下一个候选，用户侧无感；熔断后不再浪费请求去试。

想省成本的应用

用 model: "auto"，简单对话交给便宜的模型，编程和推理交给更强的模型；每次选择的理由写在响应头里。

编程工具接入

兼容 Anthropic Messages 和 OpenAI Responses 协议，Claude Code、Codex 类工具改个地址就能用。

自建模型统一管理

vLLM 等 OpenAI 兼容的自建服务可作为一个上游接入，和商用模型一起参与路由、计量。

快速开始

三步接入

  1. 1

    部署网关

    私有部署用 docker compose up -d；或联系我们开通试用环境。

  2. 2

    创建密钥

    在开发者控制台创建 API 密钥，按需设置可用模型、有效期、消费上限。

  3. 3

    改 Base URL

    把 SDK 的地址换成网关地址，模型写 auto 或具体模型名。

curl https://<你的网关域名>/v1/chat/completions \
  -H "Authorization: Bearer $AUTOLLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "auto", "messages": [{"role": "user", "content": "你好"}]}' -i
# 响应头 X-Router-Model / X-Router-Reason 说明选了哪个模型、为什么
from openai import OpenAI

client = OpenAI(base_url="https://<你的网关域名>/v1", api_key="<控制台创建的密钥>")
r = client.chat.completions.create(
    model="auto",  # 或 auto:quality_first / auto:cost_optimized / 具体模型名
    messages=[{"role": "user", "content": "写一个快速排序"}],
)
print(r.choices[0].message.content)
import OpenAI from "openai";

const client = new OpenAI({ baseURL: "https://<你的网关域名>/v1", apiKey: process.env.AUTOLLM_API_KEY });
const stream = await client.chat.completions.create({
  model: "auto",
  messages: [{ role: "user", content: "你好" }],
  stream: true,
});
for await (const chunk of stream) process.stdout.write(chunk.choices[0]?.delta?.content ?? "");
# Anthropic Messages 协议（Claude Code 等工具）
export ANTHROPIC_BASE_URL="https://<你的网关域名>"
export ANTHROPIC_AUTH_TOKEN="<控制台创建的密钥>"
# 请求会发到 /v1/messages，由网关路由到合适的上游

工作原理

一次请求经过什么

  1. 01

    鉴权与限流

    校验 API 密钥，检查每分钟请求数。

  2. 02

    冻结额度

    按候选模型中最贵的价格冻结余额，余额不足直接拒绝。

  3. 03

    路由与切换

    选模型并调用上游；出错或被熔断时换下一个候选。

  4. 04

    结算

    按实际 tokens 计费，多退少补，写入账单明细。

常见问题

你可能想问

现在能直接收钱吗？

还不能。余额、预授权、结算、账单都已完成，但微信支付、支付宝、Stripe 等在线支付渠道还在规划中，目前只能由管理员在后台手工入账。

接过真实的大模型吗？

适配代码已经写好，但目前只在模拟上游上测试过，还没有用真实密钥做端到端实测。页面上的性能数字测的是网关本身，不代表真实模型的响应时间。

model: "auto" 是怎么选模型的？

先根据最近一条用户消息判断任务类型（对话、编程、推理、长上下文），再按策略综合质量、价格、速度打分，只在你配置了密钥的上游里选。选择结果和理由会写在响应头里。

会不会扣成负数？

不会。请求前按候选模型里最贵的价格原子冻结余额，余额不够直接拒绝；完成后按实际 tokens 结算，多退少补。100 路并发、余额只够 10 次的测试里恰好成功 10 次。

可以用自己的厂商密钥吗？

可以。租户可以配置自带密钥，优先使用；平台只按设置收取服务费，也可以设为免费。

我的上游密钥安全吗？

上游密钥加密后存入数据库，界面和接口只显示末 4 位。用户的 API 密钥只保存哈希值，只在创建时显示一次。

价格包含模型调用费吗？

不包含。授权费只覆盖网关软件与支持；模型调用费由你直接与上游厂商结算。所有价格不含税。

源码可以拿来用吗？

不可以。仓库公开只是方便查看，保留所有权利，未经书面许可不得使用、复制、修改或分发。核心路由和计价增强以私有插件提供。
